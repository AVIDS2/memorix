## Compatibility Contract

Memorix preserves the legacy 2025-era initialize contract, including stdio and
stateful Streamable HTTP with `Mcp-Session-Id`. Memorix 1.8.4 also registers a
low-level `server/discover` compatibility adapter for the 2026-07-28 request.
Its `DiscoverResult` is complete for the required identity, versions,
capabilities, and private zero-TTL cache hint. Versionless `tools/list` and
`tools/call` are accepted by the pinned v1 SDK and retain its legacy result
envelopes. The stdio startup gate reads bounded newline-delimited input before
project initialization, answers discovery immediately, and replays all other
messages in order; EOF is deferred until the queued input is released. HTTP
stateless project handles remain a compatibility adapter: they
own project routing, but do not turn the v1 SDK into a complete 2026 runtime.
Tasks, subscriptions, and list-response caching are unsupported and are not
advertised or simulated.

Antigravity is the primary setup target. Gemini CLI remains a compatibility and
migration path. GitHub issue #204 (WorkBuddy) is intentionally not merged or
used as release evidence.

## Evidence Architecture

Consumers are both humans and agents. Markdown remains the human source of
truth; SQLite graph records and bounded evidence cards are the agent index.
Retrieval is hybrid/graph-assisted, but never a full graph dump. Supported
relations are persisted through the existing graph store and may reference
files, symbols, calls/imports, tests, scripts, commits, dependencies,
failures, memory, and source. Non-TypeScript/JavaScript projects use the
existing graceful fallback and report coverage honestly.

## Memory Feedback Contract

The lifecycle is capture -> qualify -> recall -> use -> feedback ->
strengthen/weaken -> archive/forget. Feedback is auditable and deterministic.
Supported signals are user correction, verification success/failure, code
change, use/non-use, and conflict with current code. Positive feedback raises
retrieval weight; negative or conflicting feedback lowers it and can make a
record eligible for archive. Recovery is explicit and auditable.

The 1.8.0 release ships the reducer, durable state/event tables, MCP and CLI
surfaces, revoke events, and tests for these rules. A legacy record without a
feedback event keeps its historical retrieval/retention score; the first
explicit feedback event opts it into the feedback projection.

## Evidence and Operator Surface

Every observation write creates or refreshes a project-scoped evidence card with
source kind, source reference, locator, captured hash, files, and freshness.
Changed paths can mark cards stale without deleting their source memory. The
`memorix_evidence` MCP tool, `memorix evidence` CLI command, and Dashboard
Evidence page expose the same persisted cards and audit events.

When MCP discovery is unavailable, `memorix context --fallback` uses a durable
one-shot budget keyed by project and task. Repeated help/search/status probing
is rejected for that task window.

## Explicit Non-goals for 1.8.0

- No fake MCP Tasks/polling implementation when the pinned SDK does not expose
  a durable server-side task contract.
- No remote memory hub, proxying of model traffic, or upstream installer.
- No claim that the bundled Lite parser is a semantic CodeGraph.
- No marketing landing page in place of an operator evidence console.
