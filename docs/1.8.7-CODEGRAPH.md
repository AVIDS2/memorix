# Memorix 1.8.7 CodeGraph Plan

Status: active implementation plan
Date: 2026-09-02

## Problem

Memorix currently has two code-context surfaces:

- the built-in Lite index, which is useful for files, declarations, and local
  import hints but is heuristic;
- an optional external CodeGraph process, which can provide semantic facts but
  is only a bounded overlay for one request.

This is honest, but it is not yet a good code-memory product. Lite does not
resolve symbols, callers, callees, implementations, or test ownership. Its
incremental refresh avoids rereading unchanged files, but it does not yet
recompute the semantic dependency closure of a changed file. The Agent can also
see different quality surfaces instead of one trustworthy answer.

## Product Decision

CodeGraph is a code-evidence plane, not a second memory database and not a
replacement for source files. Memorix will use a layered provider model:

1. current Code State: hashes, Git revision, completeness, and snapshots;
2. structural parsing: bounded local syntax facts, with a heuristic fallback;
3. semantic relations: definitions, references, calls, imports/exports,
   inheritance, and tests, each carrying source and confidence;
4. Agent context: one task-shaped receipt that says what was used, why, how
   fresh it is, and what could not be proved.

TypeScript, JavaScript, and TSX are the first semantic languages because they
are the most important local path for Memorix and TypeScript already exists in
the development toolchain. Other languages keep the existing Lite fallback
until they have a parser/resolver with equivalent evidence quality. An external
CodeGraph or SCIP index remains optional and must never be installed or
configured by Memorix.

## Evidence Contract

Every stored symbol and edge has:

- a stable project-scoped ID;
- the source (`typescript-compiler`, `lite-regex`, `scip`, or external);
- the snapshot/content version that produced it;
- a confidence value;
- a short machine-readable evidence description.

Memorix never turns an unresolved name into a confident edge. An unknown
relation is omitted or returned as an explicit uncertainty. Current source and
current Code State outrank an old memory that refers to the same file or symbol.

## P0 - Evaluation Baseline

- Add a deterministic fixture with known definitions, imports, calls, aliases,
  inheritance, and test calls.
- Record the current Lite boundary separately from semantic results.
- Measure refresh time, changed-file count, parser failures, relation counts,
  and bounded context size.
- Add negative cases for duplicate names, unresolved dynamic calls, deleted
  symbols, excluded paths, and incomplete scans.

Acceptance: the suite can say which expected relations are present, absent, or
unknown without relying on an LLM or a network service.

## P1 - AST Parsing Foundation

- Add a TypeScript Compiler API provider for `.ts`, `.tsx`, `.js`, `.jsx`,
  `.mjs`, and `.cjs`.
- Extract nested symbols with real start/end locations and stable qualified
  names: functions, classes, methods, interfaces, type aliases, enums,
  properties, and function-valued variables.
- Resolve only files inside the project boundary and honor CodeGraph excludes.
- Fall back to Lite for unsupported files or parser failures.
- Keep the provider optional at the package boundary if the runtime cannot load
  it, and report that fallback honestly.

Acceptance: TypeScript fixture symbol precision is source-backed and no longer
depends on regular expressions for the primary path.

## P2 - Semantic Relations

- Resolve local import/export targets with compiler module resolution.
- Emit definition/reference edges from resolved symbols.
- Emit calls/callees and callers from resolved call signatures.
- Emit `extends` and `implements` edges when the checker can prove them.
- Mark test-file calls as `tests` edges without guessing from filenames alone.
- Deduplicate edges while retaining the first useful source location.

Acceptance: every relation in the fixture has a source, a confidence, and a
current snapshot. Unresolved or dynamic behavior is not fabricated.

## P3 - Reliable Incremental Indexing

- Detect added, modified, removed, oversized, and unreadable paths separately.
- Reparse changed semantic files and the affected local dependency closure.
- Replace a semantic slice atomically; never expose a half-written graph.
- Keep the last completed snapshot available when a refresh fails or is
  cancelled.
- Make stale, incomplete, and queued states visible to the caller.
- Add a bounded scale test for at least 10,000 files / 100,000 symbols using
  generated fixtures without storing them in the repository.

Acceptance: a change to a callee updates callers and stale references without a
full destructive project replacement, and a failed refresh cannot claim ready.

## P4 - Unified Agent Query

- Make `memorix_project_context` / `memorix context` the primary code-graph
  entrypoint for explain, modify, debug, test, and impact tasks.
- Use one compact receipt: provider, freshness, coverage, selected relations,
  omitted material, uncertainty, and suggested next reads.
- Keep raw graph queries available for CLI diagnostics, but do not require an
  Agent to learn separate provider commands.
- Keep default output bounded and never dump full source code into a context
  pack.

Acceptance: a natural-language task receives the right code entry points and
relations in one bounded response, with no claim stronger than the evidence.

## P5 - Standardized External Providers

- Define a normalized import boundary for SCIP facts and validated external
  CodeGraph results.
- Keep external provider health, query usability, freshness, and semantic
  coverage as separate fields.
- Prefer local semantic evidence only when its project root and snapshot are
  current; otherwise use the internal provider and explain the downgrade.
- Never run a third-party installer or alter an Agent's configuration.

Acceptance: external facts can enrich a context response without contaminating
the canonical local graph or hiding an invalid/stale result.

## P6 - Product and Scale Acceptance

- Show parser coverage, relation coverage, freshness, failures, source, and
  query latency in `codegraph status`, `doctor`, and the Dashboard.
- Test Windows, macOS, and Linux through the repository CI matrix; local checks
  use Node/npm only and do not start Docker.
- Compare Lite, semantic, and external modes on the same fixture corpus.
- Track precision, recall, unresolved-rate, incremental latency, cold-start
  latency, output tokens, and task completion/tool calls.

Acceptance: the release can demonstrate improvement with reproducible evidence,
not README claims alone.

## Research Basis

The design follows the distinct roles documented by:

- [Tree-sitter](https://tree-sitter.github.io/tree-sitter/) for incremental,
  error-tolerant syntax parsing;
- [SCIP](https://scip-code.org/) for a language-agnostic code index format;
- [Kythe](https://kythe.io/docs/kythe-overview.html) for source-backed semantic
  nodes, anchors, and labelled cross-references;
- [CodeQL](https://codeql.github.com/docs/codeql-overview/about-codeql) for a
  heavier AST/control-flow/data-flow analysis tier;
- [Sourcegraph Code Graph](https://sourcegraph.com/docs/cody/explanations/code_graph_context)
  for persistent code navigation and Agent context;
- [TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API)
  for program/checker-based symbol and alias resolution.

The reported performance figures of third-party projects are not Memorix
claims. Memorix will publish only measurements produced by its own fixtures
and runners.
