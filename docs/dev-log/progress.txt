## 1.2.5 Retrieval Performance and Reliability
- Retrieval now has three explicit profiles: `fast` is fully local, `balanced`
  is the default vector-capable path without LLM query work, and `thorough`
  explicitly opts into configured LLM query rewrite/reranking.
- `OPENROUTER_API_KEY` remains an embedding fallback only. It activates the
  memory LLM lane only when that lane explicitly names an OpenRouter provider
  or base URL, preventing embedding-only configurations from adding hidden
  network work to normal search.
- Embedding, rerank, MCP search, and maintenance share one timeout helper that
  clears watchdog timers after settlement. This removes the previously measured
  avoidable CLI exit delay from a completed rerank path while preserving real
  timeouts for stalled work.
- Read-only memory CLI commands skip session-store and maintenance-target setup
  while retaining the existing project/identity visibility boundary.
- Local verification completed before release: TypeScript check; focused
  timeout/config/search/CLI/SDK tests; a full serial suite that reached a
  single stale Codex plugin-manifest version assertion, followed by its
  dedicated passing recheck after the template was synced; production build;
  package SDK benchmark; real CLI smoke; and an in-memory MCP client smoke
  confirming `memorix_search.quality` and `fast` mode.
- Current benchmark evidence on Windows/Node 22: a 1,000-record hot in-process
  SDK lexical fixture measured specific lookup p50 44.603 ms / p95 96.085 ms
  and broad-query p50 160.903 ms / p95 171.878 ms. This excludes CLI startup,
  MCP transport, remote embeddings, and LLM work by design; the two query
  shapes are reported separately rather than averaged into a marketing number.

## 1.2.4 Persistent Memory Delivery
- Continuation is now a bounded delivery projection over existing sessions and
  durable observations, not a second handoff database. `TaskWorkset` keeps its
  task lens (`bugfix`, `feature`, and so on) while independently recognizing a
  continuation request.
- A continuation Workset includes at most the latest meaningful completed
  session summary plus three readable durable memory anchors. Each item is
  visible in the existing `ContextReceipt`; ordinary tasks do not receive it.
- `memorix resume "<task>"` is the CLI-equivalent continuation entry. The
  existing MCP `memorix_project_context` receives the same behavior from the
  user's task text, so the micro MCP profile stays at seven tools.
- Setup-generated rules now use a single fallback call when MCP is genuinely
  unavailable: `memorix resume` for prior work or `memorix context` for new
  work. They explicitly forbid help probing, command enumeration, and broad
  search loops before the first brief.
- The visibility reader is carried into continuation retrieval, preserving
  project aliases while failing closed for other agents' personal memory.
- Continuation text preserves whole technical identifiers instead of emitting a
  misleading partial token. MCP Project Context also establishes a short-lived
  delivery boundary: a follow-up search/detail request does not re-send an
  already represented record unless the caller names a missing fact or the user
  explicitly asks for the underlying detail.
- A read-only or "do not modify files" Autopilot task blocks `memorix_store`
  by default. The only override is an explicit user request to persist a
  record, represented by `overrideReadOnly: true`.
- A real Codex user-path smoke, in a fresh Git fixture seeded only through the
  public CLI, made one natural-language continuation request. Codex received
  the bounded brief, used one specific Context Pack expansion, was stopped
  from re-reading already-covered memory, made no `memorix_store` write, and
  returned the correct read-only next step.
- Completed local gates: TypeScript check, production build, focused
  continuation/hook/CLI regressions, and the full suite (`237` files / `2677`
  tests). A fresh packed install with optional native dependencies omitted used
  Node SQLite to persist the same `memorix.db`; CLI resume retained
  `AUTH_REFRESH_V2`; the micro MCP package surface exposed exactly seven tools
  and enforced duplicate-retrieval plus read-only-write boundaries; and an
  isolated Codex global setup wrote/activated the versioned Personal-marketplace
  plugin with the matching skill guidance. Pending release gates: CI and
  publish.

## 1.2.3 Session Context Visibility Hotfix
- A real installed-package CLI smoke found that a second coordination identity
  could receive the first identity's personal observation in automatic session
  context. The root cause was a reader-less core session-context call.
- `getSessionContext()` now accepts an `ObservationReader`; CLI, MCP, and TUI
  session entry points pass their resolved caller identity. Alias-backed
  project-visible records remain readable, while personal/team records fail
  closed.
- Graph-neighbor routing is omitted whenever a reader is present because graph
  relations are not yet visibility-scoped. Core, CLI, MCP, and alias regression
  tests cover the boundary.

## Phase 0 Evaluation Foundation

  cases. Its seed manifest covers observations, Git facts, test evidence,

- The harness compares memory-only, current-context, and candidate Worksets
  against source/evidence/caution requirements and variant token ceilings.
- The current Auto Context path is smoke-tested against real local TypeScript
  and dirty-worktree fixtures with embeddings disabled. The candidate budget is

## Phase 1 Code State
- Lite refresh now appends a Code State Snapshot with bounded Git revision and
  worktree metadata, a source epoch, a prior-snapshot link, and explicit scan
  completeness.
- Current files, symbols, edges, and current observation-code refs are marked
  with the latest completed snapshot. Existing CodeGraph rows survive the
  additive schema migration.
- Project Context, the CodeGraph MCP status payload, and the codegraph CLI
  status output expose the latest snapshot. A non-Git directory reports
  unavailable instead of clean.

## Phase 2 Claim Ledger
- SQLite now has additive, transactional tables for claims, evidence
  references, and lifecycle events. Every stored claim requires at least one
  source reference and credential values are sanitized before durable writes.
- Exact normalized assertions reuse their record and attach more evidence;
  competing approved assertions remain disputed rather than being overwritten.
  Evidence-aware supersession preserves an audit trail.
- Explicit memories and Git-ingested facts can derive conservative claims.
  Hook/model output does not become approved knowledge automatically.
- Observation code references inherit the latest Code State Snapshot when they
  are created. CodeGraph refresh requalifies bound claims: changed or deleted
  symbols become unknown, and incomplete scans force review instead of false
  certainty.
- Unit and integration tests cover evidence validation, redaction, conflict,
  supersession, model-review policy, snapshot binding, changed-symbol
  requalification, and compact task selection.

## Phase 3 Knowledge Workspace
- Memorix now initializes a private local Markdown workspace by default. A
  versioned workspace requires an explicit absolute path inside the Git project
  and refuses ignored or unsafe target directories.
- Approved active claims compile into Markdown proposals with frontmatter,
  source claim ids, evidence references, snapshot context, a catalog, and an
  append-only change log. Proposed pages are not silently published.
- The knowledge init, status, compile, apply, and lint commands provide the
  operator path. Applying a proposal protects a manual page edit by default;
  an explicit force flag is the only overwrite path and is logged.
- Workspace lint detects malformed frontmatter, broken links, orphan pages,
  missing claims/evidence, superseded claims, unresolved conflicts, stale code
  snapshots, and protected manual edits.
- The compiled CLI was smoke-tested in an isolated Git project through init,
  compile, apply, and lint with a source-backed claim.

## 1.2.2 Control Plane
- `TaskWorkset` already has bounded rendering and source-aware claims, but
  SessionStart handoff and legacy context surfaces need one shared admission,
  budget, and receipt contract.
- First implementation slice complete: the shared `ContextReceipt` records
  delivery target, selected source ids/kinds, trust/freshness, exact budget
  omissions, queued refreshes, and Workset selection time without entering the
  agent prompt. Project Context, Context Pack, and full SessionStart injection
  now carry the same delivery-target semantics; `memorix explain` exposes the
  receipt in text and JSON.
- Budget selection now keeps a knowledge page dependent on a Claim out of the
  prompt when its qualifying Claim could not fit. The receipt records both as
  withheld instead of presenting an orphaned page path as usable knowledge.
- Phase 3 admission slice complete: automatic observations now persist an
  `ephemeral`, `candidate`, or `qualified` state and a reason. Hooks and the
  internal orchestrator capture concrete evidence as candidates, keep routine
  success/telemetry ephemeral, and drop low-signal activity without writing it.
  Automatic capture stays quiet in the host agent.
- A deduplicated `observation-qualify` maintenance job runs after CodeGraph
  refresh. It requires a scan no older than the capture and at least one
  current code reference before upgrading a candidate. Qualification does not
  create a Claim; explicit saves and Git remain the Claim boundary.
- Auto Project Context, automatic session L1 delivery, Wiki/Knowledge Graph
  compilation, and graph-context packets exclude candidates and ephemeral
  traces. Ordinary search prefers qualified material, while explicit lookup
  can still inspect pending evidence.
- Pending automatic evidence is also excluded from automatic consolidation so
  a later qualification can still inspect its original source grain. Retention
  explanations no longer describe an unqualified `core` candidate as immune.
- Actor and visibility enforcement is now one policy shared by MCP retrieval,
  auto context, CLI/TUI, dashboards, knowledge/graph projections, and scoped
  maintenance. Legacy observations remain project-visible; new records may be
  `project`, `team`, or `personal` with an explicit creator and recipients.
  Missing identity never grants private or team visibility.
- Automatic hooks and orchestrator traces begin personal. A verified hook
  candidate may become project evidence only when qualification proves a
  current code reference. Targeted handoffs are readable by sender and
  recipient but writable only by sender; broadcasts require an active project
  team member.
- Automatic orchestration lesson lookup is explicitly project-scoped, so its
  prompt injection cannot read personal or team-scoped records.
- Topic-key writes now check mutation scope before storage, and the
  project-attribution guard receives only memories visible to its current
  reader. This closes both guessed-key overwrite and cross-project existence
  hints without hiding historical project knowledge after upgrade.
- The embedded SDK remains project-visible when unbound. CLI and the local TUI
  now share the same explicit actor reader: an unbound terminal sees project
  memory only, while `memorix identity join|use` (or one-shot `--as`) grants
  only that active project member's personal/team visibility and coordination
  ergonomics. `identity clear` returns to project scope; private evidence
  cannot be promoted into shared skills or generated project skills.
- CLI control-plane ergonomics now include `--cwd`, kebab-case flag aliases,
  action-oriented namespace help, explicit `memorix workbench`, and
  file/stdin transfer import/export. Root memory aliases use the same
  canonical command paths as `memorix memory`; CLI and MCP exports are filtered
  by the same active reader so an unbound backup cannot contain private/team
  observations.
- Direct CLI and foreground Code Memory refreshes now enqueue qualification as
  well as claim requalification, and they register the local project target
  needed by the isolated control-plane worker. The host hook path persists its
  candidate before scheduling a refresh, avoiding a fast-worker race where a
  scan could predate the capture.
- Compiled-artifact smoke: an isolated Codex `PostToolUse` hook returned only
  `continue: true`, stored a `candidate`, and the isolated background control
  plane upgraded it to `qualified` after a real Code Memory scan with one
  current reference. Embeddings were deliberately disabled for this
  deterministic local smoke. The full test suite, TypeScript check, and
  production build also passed after the admission policy was reconciled with
  OpenCode's concise technical response events.
- #135 remains a contributor-owned session-handoff candidate for the bounded
  `HandoffPacket` phase. It is not copied or silently replaced.
- #133/#134 remain open pending an official provider-capability layer and a
  safe agent-facing media path. The existing OpenRouter text embedding path is
  the supported baseline.
- See [1.2.2 Memory Control Plane](../1.2.2-MEMORY-CONTROL-PLANE.md) for
  phases, acceptance gates, non-goals, and release criteria.

## 1.2.7 Native Context Continuity
- Added a project-scoped SQLite checkpoint store that separates host-native
  compaction evidence from Observations, claims, Knowledge Workspace pages,
  and transcript storage. It captures preflight markers, native summaries
  where the host exposes them, lifecycle-only completion where it does not,
  idempotent retry handling, one-time delivery state, and archival.
- Pi and Oh-my-Pi extensions now pass through their real `compactionEntry`
  fields. Codex and Claude Code use their documented compact lifecycle paths
  without fabricating a host summary or changing the host compactor.
- Codex consumes one bounded checkpoint at compact `SessionStart`; Claude Code
  consumes one on the next official `UserPromptSubmit` delivery point. Explicit
  CLI/MCP continuation can carry at most one recent source-labelled checkpoint
  across configured agents, while ordinary new tasks remain free of it.
- Added `memorix checkpoint list|show|context|archive` and the full-profile
  `memorix_compaction_checkpoint` MCP action. The default MCP profile remains
  unchanged to protect agent context budgets.
- Final verification passed: focused compaction, hook, Workset, CLI, and MCP
  tests; the full root test suite; TypeScript check; production build; npm
  package dry-run; an isolated installed-artifact Codex/CLI/MCP smoke; and an
  isolated Claude Code handoff/continuation smoke. `npm publish --dry-run
  --ignore-scripts` accepted the public 1.2.7 tarball; the full prepublish
  build/test path is covered by the root release gates above.
